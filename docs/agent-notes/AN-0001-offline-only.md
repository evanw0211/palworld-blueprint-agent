# 蓝图预览与交付只在离线侧完成

- **状态：** accepted
- **日期：** 2026-10-19
- **取代：** None
- **被取代：** None

本记录确定本仓库的工作边界：校验、导出、预览全部离线完成，不在游戏进程里建造或渲染。它约束的是预览与交付路径，以及后人能否把引擎内自动化重新加回来。代价与证据都写在这里，新增引擎内路径前先读完本页。

## 背景

蓝图预览需要「像不像」的验收，但引擎内方案带有直接风险。2026-10-18 曾用 UE4SS/UEBridge 在游戏内做 SceneCapture 缩略图与建造实验：链路能跑通（桥接 ping 成功、`GetBounds()` 与 pak 导出的包围盒一致），但记录在案的是两次独立事故。第一次，引擎内渲染实验未拦截空场景，导致游戏崩溃一次。第二次，临时 `DirectionalLightComponent` 残留把世界颜色冲白，根因是 `pcall(DestroyComponent)` 在 UE4SS 环境下静默失败、不抛错。约束因此不是「技术上做不到」，而是「失败会伤到用户的游戏会话与存档，不能作为默认或自动化路径」。证据：`archive/research/agent_blueprint_requirements.md` 的硬约束「不要自动在游戏里建造/放组件……引擎内渲染实验（未拦截空场景）导致游戏崩溃一次；渲染类操作必须默认离线」，以及 [UEBridge安装状态.md](../../archive/ue4ss/UEBridge安装状态.md) 的完整时间线——安装与实拍进度、纯黑渲染的根因、光源残留事故与清理验证。

## 决策

本仓库只在离线侧工作：不建造、不注入、不调用游戏引擎渲染。预览改用从 pak 导出的真网格，在本仓库自带的渲染页面里出图——相机公式逐行移植 mod 的 `BlueprintThumbnailRenderer`，契约与保真度证据归 [render/README.md](../../render/README.md)。游戏内导入与放置不在本仓库范围内，始终由人完成。

## 被否方案

| 方案 | 否掉的原因 |
|---|---|
| 引擎内 SceneCapture 缩略图（UE4SS/UEBridge） | 能出图，但要注入游戏进程；未拦截空场景的实验崩过一次游戏，光源残留还污染过世界光照。作为默认或自动化路径风险不可接受。 |
| 引擎内自动建造 / 放置组件 | 直接写游戏世界状态，失败可能损坏存档或卡住会话；放置门禁又依赖地形与服务器，离线无法完整预检。 |
| 只出方块代理图的离线方案 | 不碰游戏，但只到方块级，分不清墙、门、窗与屋顶形态，验收价值不足；真网格离线渲染已证明同机位轮廓可与 mod 缩略图对齐。 |

## 后果

### 正面

- 不碰游戏进程：校验、导出、渲染都能在无游戏会话时重复执行，脚本失败不会影响存档或世界光照。
- 几何与取景和 mod 缩略图一致，轮廓级验收可离线完成；本仓库已按此路线交付 5 个样本并按同一相机公式产出对照图（见 [render/compare](../../render/compare/) 与 [render/README.md](../../render/README.md)）。

### 负面

- 材质与光照不同：GLB 不含贴图，渲染页面按构件族上类型色，只能看轮廓、层数、体量与开口位置，不能判断游戏内观感。
- 无法机器确认「游戏内能否放置」：地形平整度、重叠门禁、服务器规则都要进游戏才知道，这一步始终由人导入确认。
- 相机公式与网格导出是 mod 版本的快照；mod 改渲染实现或坐标约定后，对照图需要重出。

### 后续

- 补齐 `meshes/` 的网格导出覆盖：当前 `_id_to_bp.json` 只映射 18 类，社区蓝图用到 49–55 类时会出现缺件。Owner：仓库维护者（排入后续数据/渲染任务）；触发条件：渲染社区样例出现 `status.missing` 非空。
- 若 mod 提供安全只读的接口或版本更新改变渲染后端，重新评估本决策。Owner：仓库维护者；触发条件：mod 版本变更或对照图出现系统性偏差。

## 合规

不变量：本仓库的任何脚本与文档都不得以默认路径建造、注入或调用游戏引擎渲染；预览只走 `render/` 的离线页面，数据只走 `tooling/` 的离线命令，游戏内动作由人完成。本仓库没有自动检查这一条；执行者是仓库维护者在评审新脚本时的红线审查，红线原文见 [AGENT.md](../../AGENT.md)。新增引擎内路径必须先以新记录取代本记录（supersede），并为脚本指定新的可执行位置；`archive/` 只收不可再生的记录，不收可运行代码。
