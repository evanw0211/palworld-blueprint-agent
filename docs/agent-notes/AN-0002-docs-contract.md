# 文档即契约：kind、唯一 owner、证据门槛

- **状态：** accepted
- **日期：** 2026-10-19
- **取代：** None
- **被取代：** None

本仓库的文档是 agent 进入工作的第一入口，因此按可机械校验的契约写：每页一个 `kind`、固定的入口节、每条事实只有一个 owner，命令类声明必须有实跑记录。代价是改一条事实要同步 owner 页与链接页，换来的是不再出现两份互相矛盾的说明。

## 背景

2026-10-19 审计 5 页文档时发现三类问题：没有 `kind` 元数据与入口节；同一批事实（网格常量、导出退出码、catalog 计数）散落在 4 页；并且有假声明——`tooling/README.md` 写「文件错误退 2」，实测是 1；`refresh.md` 声称重跑过生成器，实际没有。

## 决策

1. 每页 frontmatter 只有 `description` 与 `kind`，kind 取自 doc skill 的模板表；决策笔记不写摘要与目录。
2. 入口节固定：`## 摘要` → `## 目录` → `-----` → 正文 → 页尾 `## Dev Note`。
3. 每条事实一个手写 owner，其它页只链接：

| 事实 | owner |
|---|---|
| schema-9 字段、PWB9D 帧、网格/高度/朝向常量、连接属性、id 语义、catalog 结构与计数 | [data/format.md](../../data/format.md) |
| authoring 字段、CLI 用法与退出码 | [tooling/README.md](../../tooling/README.md) |
| 数据刷新流程 | [data/refresh.md](../../data/refresh.md) |
| 预览页契约与保真度证据 | [render/README.md](../../render/README.md) |
| 样本与社区参考样例 | [examples/README.md](../../examples/README.md) |
| 冻结历史 | [archive/README.md](../../archive/README.md) |
| 耐久决策 | [本目录](README.md) |

4. 文档里每条命令必须在当前修订实跑过；跑不了的标注「未复现 + 责任人」。
5. 生成文件不套入口节，但必须带「生成、勿手改」说明与生成器指向。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 不用 kind，靠目录约定 | 无法机械校验，改一处标题或链接就可能静默失效 |
| 每页各自维护一份常量、退出码或计数副本 | 已经产生过实际矛盾：导出退出码、生成器是否重跑的声明都对不上实测 |
| 把格式、CLI、刷新全塞进根 README | 入口页过载，查一条事实要扫整页，且模型每次都要加载无关内容 |

## 后果

### 正面

- 可机械校验：11 页手写文档 + 决策笔记，frontmatter、kind 映射、ToC↔H2、锚点、链接、摘要句数、数值所有权一次跑完 0 失败。
- 事实变更只需改 owner 页并修链接；评审时不必全库搜索同一句话。

### 负面

- 新增事实前先要决定 owner；跨页改动从 1 处变成 2–3 处。
- 入口节与 Dev Note 是固定开销，短页也要写。

### 后续

- 新增页面必须声明 kind 并纳入校验脚本；某类页面反复出现时，先加模板再批量改写。

## 合规

不变量：任何手写页面必须有 `kind` 且被校验脚本覆盖；同一事实不得在两个手写页里各写一份；命令类声明必须有实跑记录，或明确标注「未复现 + 责任人」。执行者：评审时的人工红线 + 校验脚本。
