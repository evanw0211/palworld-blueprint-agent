# Agent Notes — 决策笔记

## 摘要

本目录存本仓库的**耐久决策**：为什么工具链、文档和入库范围是现在这样，当时否掉了什么，什么条件下该重新考虑。agent 和人动手改工具链、文档或资源边界前先读这里，避免重开已经用实测或事故关掉的方案。一条决策一个文件，状态只有 `proposed` / `accepted` / `superseded` / `rejected` 四种；`archived/` 只收不再指导未来工作、但历史理由值得留痕的记录。本页是这些笔记的规则与索引，不重复笔记本身的内容。

## 收录标准

满足下面任一条才写一条笔记；否则写进对应 owner 页或 [archive/](../../archive/README.md)：

1. 决定了一个**边界**：能做什么、不能做什么、谁拥有哪块事实。
2. 否掉了**仍然诱人**的方案，且理由来自实测或事故。
3. 有**重新考虑的触发条件**，后人必须知道。

不收录：机械改动、一次性修复、以及能由代码本身表达的规则（写进 `.gitignore`、脚本或 owner 页即可）。

## 笔记格式

- 命名 `AN-<四位序号>-<短横线 slug>.md`；序号只增不改，一条决策一个文件。
- frontmatter 只有 `description` 与 `kind: "decision-record"`；kind 显式声明，不依赖目录名推导（本目录沿用仓库自己的 Agent Notes 约定）。
- 正文顺序：H1 标题 → 状态行（`状态 / 日期 / 取代 / 被取代`）→ 一屏内说清「决定了什么、代价是什么」的导语 → `## 背景` → `## 决策` → `## 被否方案` → `## 后果` → `## 合规` → `## Dev Note`。
- 决策笔记不写 `## 摘要` 与 `## 目录`（doc skill 对 decision-record 的例外）。

## 状态与生命周期

| 状态 | 含义 | 处理 |
|---|---|---|
| `proposed` | 提出但未采纳 | 留在本目录，永不归档；不再推进就地改 `rejected` |
| `accepted` | 已采纳并在用 | 留在本目录；被新笔记取代时改 `superseded` 并互链 |
| `superseded` | 被新决策取代 | 默认保留（决策可被引用为历史），链接改指新 owner |
| `rejected` | 明确否掉 | 仅当该方案仍可能被重新提出时保留；否则删除并修好入链 |

判断依据是代码、配置、owner 页与更新的笔记，笔记自己的状态行只是声明，不是证据。

## 归档与封存

`archived/` 收「不再指导未来工作、但历史理由值得留痕」的**完整记录集**（笔记及其必须同步的伴随文件），路径镜像本目录、不带生命周期层。

- 归档只允许一处改动：在状态行下加 `Archived: YYYY-MM-DD`。不改正文、不修外链、不翻译、不重排。
- 归档前先把活文档里的入链改指当前 owner，或删除该链接。
- 封存要求：一条记录集一个哈希，封存后不得再编辑、移动或翻译；校验必须是「先证明已有封存仍然匹配，再只追加新记录哈希」的追加式检查。
- 本仓库**尚无归档记录，也尚未实现封存校验**：第一次归档时先按本节补上校验与「篡改已封存记录必须失败」的用例，再归档。
- 恢复某条决策：写一条新笔记引用归档记录，不把归档记录移回本目录。
